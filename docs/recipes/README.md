# Contributor recipes

These recipes point to the running examples in this repository. Keep the API contract, server validation, database behavior, UI state, and tests close to the feature they explain. The package boundaries are shown in [the architecture overview](../architecture.md).

1. **Add a domain field and migration.** Add the column and constraints in a new migration under `packages/db/src/migrations`; update the Kysely interface in `packages/db/src/types/database.ts`, schema drift expectations in `packages/db/src/schema-check.ts`, and only then update the feature-specific repository and tests. Add a forward migration instead of editing an applied migration.
2. **Add a REST endpoint and permission.** Define its request and response schemas and endpoint entry in `packages/contracts/src/index.ts`; implement a thin route and feature service in `apps/lending-api/src`; authorize with the session permission middleware from `packages/server-platform/src/auth.ts`; add a typed caller in `packages/api-client/src/index.ts` and test success, validation, authorization, and conflict behavior.
3. **Fetch data with cancellation.** Add a feature function in `apps/lending-web/src/features/*/api.ts` using the shared API client and pass the query's `AbortSignal` from TanStack Query. Keep keys near the feature and invalidate the smallest affected prefix after writes.
4. **Add a metadata-driven or custom form section.** Define known fields and safe rules in the product-family metadata fixture; use `MetadataField` from `packages/ui/src/fields.tsx` for registered widgets. Add an explicit custom section only when the field needs domain-specific interaction, and keep server validation authoritative.
5. **Add a URL-driven table.** Follow `apps/lending-web/src/features/scenarios/ScenarioListPage.tsx`: parse filters, sort order, and pagination from URL search params; declare server processing explicitly; use an allowlisted sort field and stable server ordering; test reload, back/forward, and empty-result behavior.
6. **Add an editable cell and safe autosave.** Keep the cell mutation version-checked, disable automatic retries for unsafe writes, retain the user's dirty value on error, and surface 409 conflict recovery. The scenario table and detail autosave hook are the reference in `apps/lending-web/src/features/scenarios/`.
7. **Add a lazy route and navigation item.** Add the lazy import, route, and not-found/error handling in the app router, then register the visible link in the authenticated shell's navigation configuration. Keep the route component inside the shared app layout and add a route smoke test.
8. **Add and publish a business-unit metadata override.** Keep the base revision, business-unit scope, and shallow override separate; resolve them through `resolveMetadata` in `packages/metadata/src/index.ts`. Draft edits and publish use expected versions, and publishing changes one scoped pointer plus an audit event in one transaction.
9. **Add a feature flag.** Register its key, owner, purpose, and safe default in `packages/server-platform/src/flags.ts`; evaluate sensitive gates on the server with actor/business-unit context. Do not use browser visibility as authorization, and test the provider-failure policy.
10. **Investigate a bad record.** Start with the bounded audit endpoint and event ID, then use the recorded request/trace ID to find correlated API activity in the [operations guide](../operations.md). Avoid copying customer payloads into logs or telemetry. For older events, follow the archive manifest and replay procedure documented there.
11. **Create another React app or Express API.** Add an app under `apps/` with its own package manifest and TypeScript config; use `packages/ui`, `packages/api-client`, and `packages/contracts` in browser code. For APIs, call `createApplication` from `packages/server-platform` and initialize telemetry before importing instrumented modules. Register health checks and add the app to the workspace task graph and deployment workflow.
12. **Run a PR preview or release one app.** Use the [operations guide](../operations.md) and GitHub Actions workflows under `.github/workflows/`. Previews must receive isolated synthetic data per PR; release artifacts are identified per application. Configure branch protections and deployment environments in GitHub, validate Terraform, and use the documented cleanup job before deleting preview infrastructure.
